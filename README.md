# KLM · Онлайн-панель подбора КОМ

Концепт-прототип веб-приложения для подбора коробок отбора мощности (КОМ) к шинопроводу KLM.
Сделан по техническому заданию «Онлайн-панель подбора КОМ KLM», редакция 2.0.

Инженер вводит параметры трассы и отвода — панель проверяет конфигурацию по девяти правилам
справочника, подбирает минимальный достаточный корпус и собирает код заказа из девяти позиций.
Недопустимая конфигурация в заказ не уходит.

> **Данные условные.** Справочник моделей, числовые пределы и грамматика кода заказа подставлены
> для демонстрации логики. Реальный справочник заменяется без изменения интерфейса.

## Как это устроено

Статическое приложение, весь расчёт выполняется в браузере — ни сервера приложений, ни базы данных.

- `lib/catalog.ts` — справочник подмодуля КОМ: ряд коробок отбора, аппараты защиты, IP, совместимость
  с сериями. Серии не дублируются — берутся из `lib/klm-catalog.ts`, поэтому KLM-S и KLM-R
  не расходятся между разделами
- `lib/engine.ts` — расчётный модуль КОМ: десять правил, подбор корпуса, сборка строки заказа,
  кодирование конфигурации в адрес страницы. Не зависит от интерфейса
- `lib/core/klm-catalog.ts` — **реальный** справочник шинопроводов: серии KLM-S / KLM-R / KLM-T / ТПЛ,
  ряды номиналов, коробки отбора, нормы раскладки, аналоги импорта. Числа KLM-S — из официального
  каталога V3 (`data/klm-catalog/`), остальное — со снимка сайта в `data/klm-source/`.
  Расхождения между источниками помечены в коде меткой `CATALOG-V3`
- `lib/core/klm-profile.ts` — таблицы каталога V3 по номиналам: сечение, R, X, Z при 20 / 35 / 40 °C,
  габариты и погонные массы для IP55 и IP68, 4P и 5P. Отсюда берутся числа для ΔU и массы трассы
- `lib/core/select-busbar.ts` — подбор шинопровода: ток по мощности, поправки на условия
  прокладки, номинал из ряда серии, IP по среде, раскладка отводов по КОМ, проверки,
  трассировка расчёта
- `lib/core/electrical.ts` — падение напряжения, потери и стоимость потерь, токи КЗ,
  тепловое расширение, подвесы. Характеристики (R, X, I_cw, I_pk) приходят параметром
- `lib/core/cable.ts` — кабельная альтернатива: подбор сечения по ряду ПУЭ, сопротивление
  трассы, масса металла, сравнение потерь
- `lib/core/route.ts` — модель трассы: участки, изломы, точки отбора, пересечения границ;
  из геометрии собирается перечень элементов по классам раздела 8.2. Там же план для
  схемы: ломаная вида сверху, перевод «расстояние вдоль трассы ↔ точка плана»,
  привязка к сетке 0,5 м и раскладка клика в ортогональные участки
- `components/` — интерфейс: конфигуратор, инлайновые SVG-иконки и живые схемы
- `app/` — страницы на Next.js App Router, включая `/podbor` и `/sravnenie`

Иконки и иллюстрации — инлайновый SVG без внешних библиотек. Анимация задаётся CSS-классами,
поэтому `prefers-reduced-motion` отключает движение автоматически.

## Разработка

```bash
npm install
cp .env.example .env.local     # DATABASE_URL до локального Postgres
createdb klm_dev
npm run db:migrate             # применить миграции
npm run db:seed                # тенант, организации, администратор
npm run dev                    # http://localhost:3000
npm test                       # ядро и приём заявок, без базы
npm run test:db                # тесты против настоящей базы
npm run build
npm run lint
```

## База данных

PostgreSQL, схема — раздел 10 ТЗ, миграции Drizzle только вперёд (`drizzle/`).
Заведены таблицы фундамента: тенанты, организации, пользователи, членство, сессии,
приглашения, проекты, конфигурации и их версии, журнал аудита, расчётный журнал.
Справочники, прайсы, КП и заказы появятся вместе со своими этапами — заводить их
сейчас значило бы писать мёртвую схему.

Конфигурация трассы версионируется: каждое сохранение создаёт версию с автором,
временем и снимком результата целиком. Открыть можно любую — старые никуда не деваются.
Конструктор шлёт черновик на сервер при простое 3 с (ТЗ M3.8) и параллельно держит
копию в браузере на случай закрытия вкладки.

Соединение берётся только из `lib/db/index.ts`: там маркер `server-only`, ломающий
сборку при попытке утащить строку подключения в клиентский бандл. Прямой импорт
`lib/db/client` из `app/` и `components/` запрещён линтером.

## Вход, роли и защита данных

Три рубежа, а не один:

1. **`proxy.ts`** — оптимистичная проверка: есть ли кука сессии и сходится ли подпись.
   Обращений к базе нет намеренно: Proxy выполняется на каждом маршруте, включая
   предзагружаемые. В Next 16 это бывший middleware, переименованный в Proxy.
2. **`lib/dal`** — слой доступа. Каждая функция начинается с проверки сессии и
   фильтрует по тенанту и организациям пользователя. Компоненты в базу не ходят.
   Матрица прав раздела 11.2 вынесена в `lib/dal/permissions.ts` чистой таблицей.
3. **RLS в Postgres** — второй рубеж на случай ошибки в коде. Приложение в
   промышленной среде подключается ролью `klm_app`, слой доступа выставляет
   `app.tenant_id` на соединение. Без него не видно ни одной строки.

Пароли — argon2id, память 64 МБ, три итерации (ТЗ 12.1). В куке лежит подписанный
идентификатор, в базе — только SHA-256 от токена: дамп базы не даёт войти, а сессию
можно отозвать. Пять неудачных попыток блокируют вход на 15 минут.

Журналы `audit_log` и `calc_log` только на добавление: права UPDATE и DELETE
отозваны у роли приложения миграцией, переписать историю нельзя даже при ошибке
в коде. Секреты маскируются на уровне сериализатора (`lib/audit/mask.ts`).

**Важно для развёртывания:** сейчас приложение подключается владельцем схемы,
который RLS обходит. Чтобы второй рубеж заработал, в промышленной среде строка
подключения должна использовать роль `klm_app`.

Стек: Next.js 16.3 (App Router, Turbopack), React 19.2, TypeScript, Tailwind CSS v4,
PostgreSQL + Drizzle, argon2id.

`npm audit` показывает 4 предупреждения среднего уровня в цепочке `drizzle-kit → esbuild`.
Уязвимость касается только dev-сервера esbuild и не попадает в сборку, а предлагаемая
npm «починка» — откат drizzle-kit до 0.18.1, то есть на мажорную версию назад.
Оставлено сознательно; по ТЗ 12.4 сборка блокируется на критических, а не на средних.

## Данные заказчика

`data/klm-catalog/` — **официальный каталог «Шинопроводные системы KLM» V3 от 24.03.2026**,
27 страниц, старший источник по серии KLM-S. Текстового слоя в PDF нет (выгрузка из CorelDRAW),
поэтому таблицы читались рендерингом страниц в 300 dpi; порядок повторного разбора и таблица
«страница → куда легло» — в `data/klm-catalog/README.md`. Там же пять открытых вопросов к КЛМ.

`data/klm-source/` — локальная копия публичного сайта КЛМ (снимок 2026-08-05): 537 страниц HTML,
221 товар с характеристиками, 10 категорий каталога, карта сайта, JS-бандл. Логотип и иконки —
в `public/klm/`, 50 фотографий объектов — в `public/klm/objects/`.

Панель `/podbor` считает целиком на локальных данных: если сайт-источник станет недоступен,
работать она не перестанет — ссылки на первоисточник останутся только справочными.
Порядок обновления снимка — `data/klm-source/README.md`, скрипты — `scripts/mirror-klm.mjs`
и `scripts/extract-klm.mjs`.

## Что в расчёте шинопровода реальное, а что отраслевое

**Источник числовых данных KLM-S — официальный каталог V3 от 24.03.2026**, он лежит
в `data/klm-catalog/` вместе с разбором, какая страница куда легла. Оттуда взяты:
ряд номиналов 160–6300 А, сопротивления R и X, габариты и погонные массы, длины секций,
габариты углов, норма компенсаторов, параметры огнестойкой проходки, диапазоны коробок отбора.
Сайт заказчика остался источником по KLM-T, ТПЛ и аналогам импорта.

Отраслевые допущения, помечены `ponytail:` в коде:
- поправка на температуру — таблица k1 с отсчётом от **35 °C** (ГОСТ Р МЭК 61439-1:
  номинал нормируется при среднесуточных 35 °C, максимум 40 °C): 35 → 1,00 · 40 → 0,97 ·
  45 → 0,94 · 50 → 0,90 · 55 → 0,86, между точками линейно, выше 55 °C — предупреждение;
- норма запаса по току 15–35 % — ниже 15 % выдаётся предупреждение;
- шаг подвесов и расчётный перепад температуры шин — каталогом не заданы.

**Потеря напряжения считается** — ΔU = √3·I·L·(R·cosφ + X·sinφ) на сопротивлениях каталога,
предел 5 % для участка ТП → ГРЩ и 4 % для распределительной трассы. Для KLM-T и ТПЛ данных
по-прежнему нет, там остаётся отметка «проверить отдельно».

**Стойкость к КЗ не считается:** `I_cw` и `I_pk` по номиналам в каталог не вошли, есть только
общее «до 150 кА» с сайта.

### Что каталог исправил в справочнике

| Было (по сайту) | Стало (каталог V3) |
|---|---|
| ряд 160–2000 и 10 000 А | 160–6300 А, добавлены 315 и 500 А |
| 160–2000 А только в меди | медь и алюминий на всём ряду |
| IP54 / 55 / 65 / 68 | IP55 / IP68 |
| у магистрали нет окон отбора | Plug-in в окно до 630 А, Bolt-on на стык до 1250 А |
| с окна снимается 250 А | 630 А |
| компенсаторы по допуску стыка | норма завода: Al 30 м, Cu 45 м прямого участка |
| габариты углов неизвестны | CD 435 мм, CP по номиналу — длина вычитается из участков |
| KLM-R 100–1600 А | **160–630 А** (уточнено заказчиком 14.08.2026) |

Шаг окон отбора заказчик назвал проектным параметром — он задан значением по умолчанию
0,5 м и переопределяется на объекте. Ширина меди 315 А IP55 в каталоге (170 мм) подтверждена
как опечатка, в коде 140 мм. Токи КЗ и прайс заказчик снял с повестки: стойкость к КЗ
остаётся непосчитанной, цена и КП ждут своего этапа.

Ток нагрузки: `I = P·Kс / (√3·U·cosφ)`. В режиме ввода тока Kс не применяется повторно —
расчётный ток проекта уже содержит одновременность.

## Что в расчёте КОМ реальное, а что заглушка

Реальное — со страниц `/catalog/korobki-otvetvitelnye-tapp-off`:
ряд номиналов 16 / 32 / 63 / 125 / 160 / 250 / 400 / 630 А, аппарат защиты по номиналу
(до 63 А — автомат C/D, от 125 А — с термомагнитным расцепителем), IP54 / IP55, 690 В,
болтовое подключение к окну отбора, совместимость с ШРА KLM-R 250–1600 А.

Из каталога V3 (стр. 24) — коробки для магистрали KLM-S, это отдельное семейство:
**Plug-in (PB) 160–630 А** ставится в окно секции Pi, **Bolt-on (BB) 160–1250 А** —
на стык двух секций и требует стыковочный элемент GF, монтаж только на обесточенной трассе.
Ряд начинается со 160 А: мелких 16–125 А, как у тапп-офф на ШРА, здесь нет.

Заглушки, ждут подтверждения КЛМ:
- `HANDLE_THRESHOLD = 125 А` — порог обязательной рукоятки управления;
- коэффициент одновременности отводов принят 1,0 — сумма отводов сравнивается
  с полным номиналом магистрали. Прежний `LOAD_SHARE = 0,4` удалён: он занижал лимит
  в 2,5 раза и не имел источника.
